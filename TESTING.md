# Тестирование проекта

В проекте есть тесты сервиса рейтинга на Python, браузерные Selenium-тесты карты и один шаблонный тест React. Тесты проверяют разные части приложения; успешный запуск одного набора не означает, что все компоненты работают вместе.

## Тесты сервиса рейтинга

Тесты расположены в [`Project/tests/`](Project/tests/). При подсчёте функций обнаружено 67 тестов в 12 файлах:

| Файл | Число функций | Основные проверки |
| --- | ---: | --- |
| `test_aggregator_reputation.py` | 2 | Учёт нейтральных новостей в репутационной статистике |
| `test_api.py` | 9 | Оценка, поиск, досье, статистика, формат ИНН и ошибки API |
| `test_legal_events.py` | 3 | Преобразование судебных дел и работа без ключа источника |
| `test_news_parser.py` | 8 | Разбор RSS, поиск, фильтрация, дубликаты и ошибка сети |
| `test_news_sources.py` | 1 | Стандартные источники новостей |
| `test_news_url_security.py` | 3 | Доверенные и недопустимые адреса источников |
| `test_parser.py` | 8 | Парсер объектов, ответы и ошибки источника, модель проекта |
| `test_problem_objects_report.py` | 1 | Извлечение сводки по проблемным объектам |
| `test_repositories.py` | 3 | Поиск застройщиков и проектов в локальных данных |
| `test_scoring.py` | 10 | Статусы рейтинга, факторы, задержки и правовые риски |
| `test_sentiment.py` | 17 | Анализ тональности новостей и текстов |
| `test_topsis.py` | 2 | Диапазон результата TOPSIS и случай недостатка данных |

Это число функций в исходном коде, а не подтверждение успешного выполнения. Некоторые тесты используют подмены зависимостей, а часть работает с моделью анализа тональности или обращается к базе при проверке API. Для полного набора могут понадобиться настроенная PostgreSQL, данные модели и доступ к интернету при первой загрузке модели. Запуск полного набора в этой документации не подтверждён.

### Установка и запуск

В PowerShell из корня проекта создайте виртуальное окружение и установите зависимости:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r Project/requirements.txt pytest pytest-asyncio
```

Перейдите в каталог сервиса и запустите тесты:

```powershell
Set-Location Project
python -m pytest tests -v
```

Запуск одного файла или конкретного теста:

```powershell
python -m pytest tests/test_scoring.py -v
python -m pytest tests/test_scoring.py::test_scoring_high_reliability -v
```

Перед тестами, которым нужна база, настройте `DATABASE_URL` для **отдельной тестовой базы**, а не рабочей: некоторые обращения API сохраняют результаты. Настройки окружения процесса можно задать в PowerShell; доступ и схема базы должны соответствовать настройкам сервиса. Каталог `Project` используется как рабочий из-за относительных путей к данным и статическим файлам.

В `Project/tests/run_tests.py` есть вспомогательный запускатель, но для проверки результата предпочтительнее использовать непосредственно `pytest`: его код завершения отражает ошибки сбора и выполнения тестов.

## UI-тесты Selenium

В [`noHaze/frontend/my-map-app/ui_tests/`](noHaze/frontend/my-map-app/ui_tests/) находятся 10 браузерных тестов. Они проверяют:

1. Поиск с параметрами и фильтром надёжности, результат на карте и открытие досье.
2. Сброс параметров и результатов.
3. Отображение ошибки поиска.
4. Доступность основных элементов при ширине окна 1440 и 390 пикселей.
5. Скрытие и повторное открытие панели фильтров.
6. Сворачивание и разворачивание категорий.
7. Пустой результат поиска.
8. Закрытие и повторное открытие карточки объекта.
9. Ошибку загрузки досье.
10. Повторный поиск после ошибки API.

Тесты запускают временный локальный API с подготовленными ответами и не используют рабочую базу. Порт `8000` должен быть свободен; интерфейс запускается отдельно. Подробные требования и команды приведены в [инструкции Selenium-тестов](noHaze/frontend/my-map-app/ui_tests/README.md). Десять тестов проходили в Chrome при последней проверке в рамках добавления тестов; это не гарантия результата последующих запусков.

Проверка размеров окна убеждается в наличии и доступности отдельных элементов, но не является полной проверкой адаптивности или доступности. Автоматизация также не заменяет наблюдение за реальными пользователями.

## API-тесты Postman

Коллекция [postman/api.postman_collection.json](postman/api.postman_collection.json) содержит 11 запросов с проверками: состояние сервиса, поиск застройщиков и объектов, покрытие рейтингов, список источников, валидацию и запрет изменения источника без ключа. Положительные проверки поиска и покрытия требуют работающих сервисов и заполненной схемы базы; конкретное число найденных объектов не задано.

1. Запустите проект согласно [README.md](README.md) и дождитесь готовности сервисов и базы.
2. В Postman выберите **Import** и импортируйте коллекцию и пример окружения [postman/local.postman_environment.json](postman/local.postman_environment.json).
3. Выберите окружение «Новостройки — локально». При необходимости измените `nohaze_url` и `rating_url`; значения по умолчанию — `http://localhost:8000` и `http://localhost:8001`.
4. Откройте коллекцию и нажмите **Run**, выберите локальный запуск и это окружение. Результаты проверок появятся в отчёте запуска.

Запросы коллекции не предназначены для изменения данных. Проверка PATCH намеренно отправляется без ключа и ожидает `403`; не добавляйте к ней авторизацию. Не сохраняйте пароли и ключи в файлах репозитория. Другие доступные API, например обновление рейтинга, меняют данные и здесь не включены.

### Запуск коллекции через Docker

При работающих `db`, `rating-service` и `nohaze-api` дождитесь доступности обоих API, затем выполните из корня проекта:

```powershell
docker compose --profile testing run --rm --no-deps api-tests
```

Compose запустит отдельный контейнер Newman и передаст ему адреса API во внутренней сети Docker. Коллекция и окружение подключаются только для чтения. Профиль `testing` не включается при обычном `docker compose up`; команда `run` не собирает и не запускает API благодаря `--no-deps`. Если образ Newman ещё не скачан, Docker загрузит его из реестра. Код завершения Newman указывает на успех или ошибку проверок.

Для запуска в терминале установите [Postman CLI](https://learning.postman.com/docs/postman-cli/postman-cli-installation/) и выполните из корня проекта:

```powershell
postman collection run postman/api.postman_collection.json -e postman/local.postman_environment.json
```

Коллекцию также можно подключить к CI после настройки отдельных тестовых сервисов и базы. Сейчас готовый CI-процесс в проект не добавлен.

## Шаблонный тест React

Файл [`App.test.js`](noHaze/frontend/my-map-app/src/App.test.js) содержит один тест из шаблона React, который ищет текст `learn react`. Он не описывает текущий интерфейс и нуждается в переработке; его наличие не следует считать проверкой приложения. Команда `npm test` запускает React-тесты, а не Selenium-набор.
